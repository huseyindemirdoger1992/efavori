All Code Rules:

CORE PHILOSOPHY

Razor is not UI, it is an Application Host

A Razor Component represents a single use case

One component, one responsibility

State is immutable

Execution flow is deterministic

Side effects are explicit

RAZOR COMPONENT STRUCTURE

.razor → render only

.razor.cs → all logic

Code-behind is mandatory

No logic in markup

Minimal lifecycle usage

UI state ≠ domain state

Event → Command → Result pipeline

Components are orchestration units

DATABASE ARCHITECTURE (CRITICAL)

EF Core = write-only

Reads = Dapper / raw SQL

DbContext lifetime = Scoped

One DbContext per Razor scope

No tracking by default

Compiled queries are mandatory

Projection-first querying

SELECT * is forbidden

Explicit, short transactions

Implicit Unit of Work

Soft delete via global filters

RowVersion concurrency required

No query without an index

Migrations require manual review

Lock escalation must be prevented

Read-replica ready

Shard-friendly schema

Fixed command timeouts

Measured retry policies

Connection pool limits defined

DATABASE SECURITY

Parameterized queries only

Dynamic SQL forbidden

SQL Injection = build failure

Least-privilege DB users

Separate read/write DB users

Immutable audit logs

Encrypted PII columns

Feature-scoped DB access

DbContext never exposed directly

TESTING PHILOSOPHY (NON-NEGOTIABLE)

Untested code does not exist

No feature without tests

Tests are first-class citizens

Behavior over mocks

Deterministic tests only

Test code quality equals production code

Single responsibility assertions

Snapshot tests only for UI
